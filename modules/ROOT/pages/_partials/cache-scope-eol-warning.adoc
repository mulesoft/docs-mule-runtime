//CACHE SCOPE DEPRECATED CUSTOMIZATIONS//

// tag::cacheKeyGeneratorDeprecated[]
[WARNING]
====
Key Generator is deprecated. It requires implementing the `com.mulesoft.mule.runtime.cache.api.key.MuleEventKeyGenerator` interface, which operates on the full Mule event.

Applications with a `minMuleVersion` of 4.13 or later can't use Key Generator: Anypoint Studio doesn't show this option, and deploying such an application fails if it's configured. Applications with an earlier `minMuleVersion` can continue to use Key Generator.
====
// end::cacheKeyGeneratorDeprecated[]

// tag::cacheAdvancedSettingsDeprecated[]
[WARNING]
====
The Response Generator and Event Copy Strategy settings on the *Advanced* tab are deprecated. Both require a Java implementation that operates on the full Mule event. For example, Response Generator requires implementing the `com.mulesoft.mule.runtime.cache.api.response.ResponseGenerator` interface.

Applications with a `minMuleVersion` of 4.13 or later can't use these settings: Anypoint Studio doesn't show the *Advanced* tab, and deploying such an application fails if either setting is configured. Applications with an earlier `minMuleVersion` can continue to use these settings.
====
// end::cacheAdvancedSettingsDeprecated[]

// tag::cacheExtensionPointsDeprecated[]
[WARNING]
====
Key Generator, Response Generator, and Event Copy Strategy are deprecated because they require Java implementations that operate on the full Mule event.

Applications with a `minMuleVersion` of 4.13 or later can't use these customizations: Anypoint Studio doesn't show them, and deploying such an application fails if any of them is configured. Applications with an earlier `minMuleVersion` can continue to use them.
====
// end::cacheExtensionPointsDeprecated[]

// tag::cacheObjectStoreMigration[]
[IMPORTANT]
====
Applications with a `minMuleVersion` earlier than 4.13 continue to persist the full Mule event instead of the message. This behavior is controlled by the `mule.serialize.message.in.cache` feature flag. See xref:feature-flagging.adoc[Feature Flagging Mechanism].

If the Cache scope finds an entry serialized in the older, full-event format when reading from the object store, it replaces that entry with the message-only format after use. Existing entries are migrated on demand as they're accessed, rather than all at once.

After an entry is persisted in the message-only format, it can't be read by an earlier Mule runtime version. To roll back to an earlier Mule runtime version, clear the caching strategy's object store first.
====
// end::cacheObjectStoreMigration[]
